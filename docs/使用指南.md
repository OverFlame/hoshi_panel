# 使用指南

给用这个面板管 Minecraft 服务器的人看的。读完后你会：装好、登录、把一个已有的服务端目录接管进来、启停、看日志、发命令。

## 1. 这是什么

一个网页版的服务器管理面板。你在浏览器里管服务器，不用开着启动器的窗口。

当前版本能做的事：

| 范围 | 内容 |
|---|---|
| 概览 | 服务器数、在线玩家、整机内存与 CPU、最近事件 |
| 实例 | 接管已有目录、导入 zip 整合包、目录迁移、每台单独设 Java 与内存 |
| 进程 | 启动、停止、强杀、实时控制台（按级别着色） |
| 命令 | 白名单三档，可按服务器切换 |
| 文件 | 目录浏览、文本编辑、`server.properties` 保序编辑 |
| 备份 | 创建、列举、恢复、删除，后台执行带进度 |
| 导入导出 | 流式导出 zip（可取消）、安全解包导入 |
| 模组 | 侧别判定与一键启停 |
| 地图 | BlueMap 配置、`/map/` 反代、玩家位置、标记、共享链接 |
| 安全 | 两步验证、登录锁定、审计页、改密码、CSRF、JVM 参数白名单、暴露三档 |
| 通知 | QQ 机器人只读查询（状态、玩家、事件） |
| 界面 | Tabler 深色/浅色，`data/theme.css` 自定义，JetBrains Mono 字体 |

还不能做的：

| 项 | 说明 |
|---|---|
| 从零下载安装整合包 | 只能接管已有目录或导入 zip |
| Create 列车显示在地图上 | 需要第三方接口 |
| 定时重启与定时备份 | 未实现 |
| 多用户与分权 | 只有一个管理员 |
| 部分长操作取消 | 目录迁移、整合包解压还不能中途取消 |

## 2. 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 及以上，或 Linux |
| Python | 3.12 |
| Java | 17 或 21，取决于你的服务端版本 |
| 内存 | 面板本身约 45 MB，服务器另算 |

## 3. 安装

```powershell
git clone git@github.com:OverFlame/hoshi_panel.git
cd hoshi_panel

uv venv --python 3.12
uv pip install -e .

# 国内网络装不动时加镜像
uv pip install -e . --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

## 4. 第一次启动

```powershell
uv run python -m hoshi
```

终端会打印：

```
HoshiLauncher 0.1.0 · 数据目录 ./data · 配置 ./hoshi.toml
首次启动，已生成管理员密码: 8ygbKaLmwGzB6YrqMT
同时写入 data/initial-password.txt
监听 http://127.0.0.1:25566
```

浏览器打开 `http://127.0.0.1:25566`，用 `admin` 和上面那个密码登录。密码文件留在 `data/` 里，第一次登录后可以删掉。

改端口：

```powershell
uv run python -m hoshi --port 25580
```

改监听地址（**默认只给本机**，改之前先看第 8 节）：

```powershell
uv run python -m hoshi --bind 0.0.0.0
```

## 5. 把一个已有的服务器接进来

面板不复制你的文件，只记住「目录在哪、怎么启动」。所以你可以继续用手动开服，也可以随时把面板删掉，目录不受影响。

先看一眼识别结果，不写任何配置：

```powershell
uv run python -m hoshi instances detect "D:\MC\你的服务端目录"
```

正常会输出类似：

```
方式=args_file · 参数=libraries/net/minecraftforge/forge/1.20.1-47.3.33/win_args.txt
加载器=forge 1.20.1-47.3.33 · MC=1.20.1
```

确认无误再注册，并指定 Java：

```powershell
uv run python -m hoshi instances add 我的服 "D:\MC\你的服务端目录" `
  --java "C:\Program Files\Zulu\zulu-17\bin\java.exe" `
  --min-memory 2048 --max-memory 8192
```

找不到 Java 时先扫一遍：

```powershell
uv run python -m hoshi java scan
```

查看已注册：

```powershell
uv run python -m hoshi instances list
```

要点：

1. 已安装好的 Forge 或 NeoForge 服务端没有根目录 jar，靠 `@args` 启动，面板会自动识别。
2. 原版单 jar 的服端识别成 `jar` 方式。
3. `--max-memory` 按你服端需要给，4 核 16 GB 机器上建议不超过 8 GB。

## 6. 日常使用

登录后先到**概览页**：四张指标卡（服务器数、在线玩家、内存、CPU）、每台服务器的卡片、右侧最近事件。点卡片上的「进入」才到详情页。

### 概览页看什么

| 指标 | 含义 |
|---|---|
| 服务器 | 总数与运行中的数量 |
| 在线玩家 | 所有服务器合计 |
| 内存 | 整机已用 / 总量，下面一行是面板自己占多少 |
| CPU | 整机占用百分比与核心数，下面一行是面板自己占多少 |

每张服务器卡片显示状态、在线人数、内存与 CPU，可以直接启动、停止或进入详情。

### 详情页

详情页用页签切换：控制台、文件、模组、地图、备份、设置、导出 zip。

### 控制台颜色

日志按级别着色，扫一眼就知道哪里出问题：

| 级别 | 颜色 |
|---|---|
| ERROR / FATAL | 红 |
| WARN | 黄 |
| INFO | 默认 |
| DEBUG / TRACE | 灰 |
| 玩家加入 / 离开 | 绿 / 橙 |
| 面板自己的提示（`> 命令`） | 蓝 |

服务端原始文本不变，颜色只在浏览器里加。

| 按钮 | 作用 | 何时用 |
|---|---|---|
| 启动 | 拉起服务器 | 常规开服 |
| 停止 | 发 `stop`，等它自己退 | **优先用这个**，世界会正常存盘 |
| 强杀 | 直接杀进程 | 卡死时用，可能丢最近的存档 |

控制台输入框可以直接发命令，例如 `list`、`say 大家晚上好`、`save-all`。

日志会同时写进 `data/logs/instances/<实例名>.log`，重启面板后还能翻。

## 6.1 设置页

右上角「设置」按分组列出全部配置项。每项都标了：

| 标记 | 含义 |
|---|---|
| 当前来源 | `default` 默认值、`file` 配置文件、`cli` 命令行 |
| 风险等级 | high 改之前想清楚 |
| 重启生效 | 改完要重启面板 |

保存后立即写入 `hoshi.toml`，同时记一条改动历史。历史可用 `GET /api/settings/history` 查看。

## 6.2 两步验证

三种方式，按你手头的条件选一种。

### 方式一：手机验证器（扫码）

1. 设置页点「生成密钥并显示二维码」。
2. 打开验证器 App（Google Authenticator、Microsoft Authenticator、2FAS、Aegis、1Password 都行），扫描页面上的二维码。
3. 把 App 显示的 6 位数字填进输入框，点「启用」。
4. 页面会列出 10 个恢复码，**只显示这一次**，存好。

扫不出码也能用手输：验证器里选「输入设置密钥」，把页面上那串 base32 粘进去，类型选「基于时间」，位数 6、周期 30 秒。

### 方式二：没有手机，在服务器终端出码

不需要任何 App，只要你能登录服务器：

```powershell
# 第一次：生成密钥、打印地址与 10 个恢复码，并直接启用
uv run python -m hoshi totp --setup

# 以后每次登录前取当前 6 位码
uv run python -m hoshi totp
```

这条路的含义是「第二因素 = 服务器 shell 权限」。远程攻击者拿不到，但能登上服务器的人本来就能改配置。

### 方式三：只用恢复码

启用后把 10 个恢复码存到密码管理器或纸上，登录时把它们填进「动态码」框，一个只能用一次。用完可以在设置页「重新生成恢复码」再拿 10 个。

### 其他

- 桌面端也有验证器：KeePassXC、Bitwarden 桌面版、`oathtool`，都能算 TOTP。
- 关闭两步验证：设置页「关闭两步验证」，或 `hoshi totp --disable`，都要密码确认。
- 手机时间要准，差超过 30 秒会一直提示码错。

## 6.3 命令白名单

设置项 `console.command_mode`：

| 档位 | 放行范围 | 建议 |
|---|---|---|
| strict | 原版命令 + `console.extra_commands` | 默认，日常够用 |
| extended | 再加带命名空间的模组命令 `mod:cmd` | 装了模组用这个 |
| raw | 全部直送 stdin | 只在本机档用 |

被拒绝的命令不会进服端，控制台会显示一行 `[面板] 拒绝：...`。

## 6.4 改密码

设置页顶部「改密码」：填当前密码与新密码（至少 8 位）。保存后：

- 新密码立即生效；
- 其它设备上的登录会话被踢掉，当前这个保留；
- 审计里留一条 `password` 记录。

忘记密码只能在服务器上处理：

```powershell
uv run python -m hoshi reset-password
```

## 6.5 审计页

右上角「审计」，两个标签页：

| 标签 | 内容 |
|---|---|
| 操作审计 | 登录成功与失败、锁定、启动停止强杀、命令、设置改动、改密码、两步验证变更 |
| 设置改动 | 每个配置项的新旧值与操作者 |

审计保留 90 天，启动时自动清理更早的记录。可按动作过滤，例如 `login`、`command`、`password`。

## 6.6 文件管理

首页详情页「文件」页签：目录逐层浏览，点文件名打开编辑器，直接改文本（上限 1 MB）。

- 只能操作实例目录内的文件，`..` 与绝对路径会被拒绝。
- 二进制文件（含 `\0`）不允许在线编辑，会提示下载后本地改。
- 每个写操作都进审计，动作名 `file.write`、`file.delete`。

## 6.7 备份

详情页「备份」页签，备份存在 `data/backups/<实例名>/`，不进实例目录。

| 操作 | 说明 |
|---|---|
| 创建备份 | 默认打包 `world`、`config`、`mods`，后台执行，带进度与取消 |
| 恢复 | **先停服**，正在运行时接口直接拒绝（409） |
| 删除 | 单个删除，不提供批量 |

默认保留 10 份，超出按时间删最旧的。

## 6.8 导出与导入 zip

**导出**：详情页「导出 zip」按钮，把世界、配置、模组打成一个压缩包。导出用 store（不压缩），因为 jar 与世界文件本来就压过，deflate 只是白烧 CPU。

导出在后台打包，顶部会出现进度条与「取消」按钮。打包完成后自动开始下载；中途取消会删掉半成品文件。

**导入**：`POST /api/instances/<id>/import`，上传 zip 解到实例目录并覆盖同名文件。解包时逐条校验路径，`../` 与符号链接会被跳过并在响应里列出。

## 6.9 导入整合包

概览页右上角「导入整合包」，弹出四种方式：

| 方式 | 数据怎么走 | 条件 |
|---|---|---|
| 服务器上的文件夹 | 只登记目录，文件原地不动 | 始终可用 |
| 服务器上的 zip | 解压服务器上已有的 zip，不上传 | 始终可用 |
| 从我的电脑上传 | 浏览器把 zip 传给面板，再解压到服务器 | 始终可用，但要能打开面板 |
| 服务器从网址下载 | 服务器按你给的地址主动下载 | 需要打开「允许服务器从网址下载 zip」 |

四张卡片各有一句提示，说明数据流向与前提。

「服务器从网址下载」默认关闭。关着时按钮置灰，红字提示「未允许服务器从网址下载」，展开会说明怎么开与风险；接口同样返回 403，不只是界面禁掉。

这个开关与「公网暴露」无关：它管的是服务器能不能主动访问外网地址，不是别人能不能访问面板。

本地 zip 的流程：

1. 解压到 `servers_dir/<实例名>`；
2. 识别启动方式（`jar` 或 `args_file`）、loader 与版本；
3. 自动挑一个 Java 注册成实例。

「已有文件夹」走的是 `POST /api/packs/adopt`：识别目录后直接登记，不移动任何文件，适合已经在手动开的服。

「服务器上的 zip」走 `POST /api/packs/import-path`：只解压、不复制原始 zip，适合先用 scp 或 sftp 把包传到服务器的情况。目标目录已存在会返回 409。

「远程 zip」走 `POST /api/packs/import-url`：下载有进度、可取消，上限受 `files.max_upload_mb` 限制。

识别失败会返回 422 并把已解压的目录留着，这时用 `hoshi instances add` 手动补。

## 6.9.1 按服务器单独设置

一台服务器一套的东西都放在详情页「设置」页签里改，只影响当前服务器，不动其它实例。

### 实例本身

| 字段 | 说明 |
|---|---|
| Java 路径 | 可点「浏览」选 `java.exe` |
| 最小 / 最大内存 | MB |
| JVM 参数 | 空格分隔，仍受白名单限制 |
| 编码 | `utf-8` 或 `gb18030` |
| 核心 / 参数文件 | jar 文件名，或 `args_file` 的相对路径 |
| nogui | 是否追加 `nogui` |

服务器运行中不允许改，接口返回 409。

### 功能开关

| 设置 | 说明 |
|---|---|
| `map.enabled` | 这台服务器是否开地图 |
| `map.render_threads` / `map.hires_distance` | 渲染线程与高清距离 |
| `map.accept_download` | 是否为这台服务器同意 BlueMap 下载资源 |
| `map.player_poll_seconds` | 玩家位置刷新间隔 |
| `mods.side_lookup` | 是否在线查模组侧别 |
| `console.command_mode` | 命令白名单档位 |
| `console.extra_commands` | 额外允许的命令 |

每项右侧显示来源：`默认`、`全局`、`本实例`。改过的项会多一个「恢复默认」按钮，点一下回到全局值。全局设置页里同名项仍然存在，作用是新服务器的默认值。

### Java 版本要按 MC 版本选

| MC | 建议 Java |
|---|---|
| 1.20.5 与 1.21+ | 21 到 25 |
| 1.18 到 1.20.4 | 17 到 21 |
| 1.16.5 及更早 | 8 到 16 |

面板在 `instances add` 与导入整合包时会按版本自动挑，不会再无脑选最高版本。

## 6.10 模组

详情页「模组」页签列出 `mods/` 下的 jar，显示侧别与建议：

| 侧别 | 含义 | 建议 |
|---|---|---|
| 客户端 | 只有客户端需要 | 服务端可以不装，装了也不生效 |
| 服务端 | 只有服务端需要 | 保留 |
| 通用 | 两侧都要 | 保留 |
| 未知 | 判不出来 | 保守留着 |

判定顺序：`fabric.mod.json` 的 `environment`、`mods.toml` 的 `side`、内置常见模组名单，最后勾上「在线查侧别」时用 Modrinth 按 sha1 反查。

启停靠改后缀：`xxx.jar` ↔ `xxx.jar.disabled`。服务器运行中拒绝改，先停服。

「上传模组」按钮可以一次选多个 jar，直接放进 `mods/`：

| 规则 | 说明 |
|---|---|
| 只收 `.jar` 与 `.jar.disabled` | 其它文件跳过并在提示里列出 |
| 同名文件不覆盖 | 提示「已存在」，请先删或改名 |
| 大小上限 | 跟设置里的 `files.max_upload_mb` 一致，默认 4 GB |
| 生效时机 | 上传完成要重启服务器才加载 |

上传有进度条，完成后自动刷新列表。

## 6.11 编辑 server.properties

`GET /api/instances/<id>/properties` 读出键值，`PUT` 写回。写入时保留原有注释与顺序，只改对应行，并留一份 `server.properties.bak`。

运行中只读，接口返回 409。

## 6.12 目录迁移

`POST /api/instances/<id>/migrate`，body `{"target": "D:\MC\新位置"}`。

预检项：服务器必须已停止、目标不能已存在、不能是源目录的父级、目标磁盘剩余空间要够。同分区走改名（快），跨分区走复制加校验，失败清理半成品，实例记录保持原样。

## 6.13 崩溃诊断

`GET /api/instances/<id>/diagnose` 扫最近日志，命中这些模式就给人话：

| 代码 | 现象 |
|---|---|
| eula | 没同意 EULA |
| port | 端口被占用 |
| java | Java 版本不匹配 |
| memory | 堆内存不足 |
| missing_dep | 缺前置模组 |
| incompatible | 模组冲突或重复 |
| noclass | 类缺失，版本不配对 |
| watchdog | 看门狗强停 |

没命中就说没发现已知问题，不猜。

## 6.14 bot 只读令牌

设置页「bot 令牌」创建，绑定群号，令牌只显示一次。

| 接口 | 说明 |
|---|---|
| `GET /api/bot/status?format=text` | 状态，文本或 JSON |
| `GET /api/bot/players` | 在线名单 |
| `GET /api/bot/events?since=<id>` | 加入、离开、启停、崩溃事件 |

鉴权用 `Authorization: Bearer <token>`，不需要登录会话。限速：每群每分钟 10 次，每人每分钟 1 次（`X-Bot-User` 头区分）。超限返回 429 与 `Retry-After`。

文案模板与超限提示都在设置里改（`bot.status_template`、`bot.limit_message`）。

## 6.15 网页地图

地图用 BlueMap，面板只做三件事：把 jar 放到实例里、生成配置、把它的网页反代到 `/map/`。

### 安装 jar

详情页「地图」页签点「安装 BlueMap」：

1. 面板按实例的 MC 版本与加载器去 Modrinth 找匹配版本并下载。
2. 下到 `data/packages/bluemap/`，校验 sha1，再复制成 `mods/bluemap.jar`。
3. 顺便生成 BlueMap 配置。

下载有进度条，可以取消。访问 Modrinth 慢时，在设置里填 `map.download_mirror` 指向一个直链 jar，面板会跳过查询直接下这个地址。

不想要自动下载也行：自己把 jar 放到 `data/packages/bluemap/`，文件名与版本矩阵一致（MC 1.20.x 用 `bluemap-3.20-forge.jar`，1.21+ 用 `bluemap-5.x-neoforge.jar`）。

无论哪种方式，都要在设置里打开 `map.enabled`，并按 BlueMap 的要求打开 `map.accept_download`。

### 只出俯视图（最省空间）

只想看平面地图时，在实例设置里这样关：

| 设置 | 值 |
|---|---|
| `map.hires_enabled` | 关 |
| `map.free_flight_view` | 关 |
| `map.perspective_view` | 关 |
| `map.flat_view` | 开 |

这样 BlueMap 只写低分辨率的平面瓦片，hires 的 3D 模型文件不再生成，体积能降一个数量级。

两个注意点：

1. **已有的 hires 瓦片不会自动删**。关闭后旧文件仍在磁盘上，用地图页签的「清理已渲染瓦片」删掉，释放空间后再重新渲染。
2. 只出俯视图时，网页端就没有自由飞行与斜视角，只剩平移缩放。

### 生成配置

`POST /api/instances/<id>/map/config` 会一次写出整套 BlueMap 配置：

| 文件 | 关键项 |
|---|---|
| `core.conf` | `accept-download`、数据目录、渲染线程、更新冷却、全量更新间隔、区域文件检查间隔、是否扫描模组资源、metrics |
| `storages/file.conf` | 存储类型 file、webroot、压缩方式（gzip / zstd / deflate / none） |
| `webserver.conf` | 启用内置网页服务、webroot、端口（默认 8100）、SSE |
| `webapp.conf` | 启用 webapp、默认是否平面视图 |
| `maps/overworld.conf` 等 | 世界路径、维度、显示名、排序、起始坐标、天空与虚空颜色、光照、洞穴剔除高度、最小停留时间、渲染范围掩码、边缘渲染、三种视图开关、是否启用 hires、存储指向、marker-sets |

这些值都按实例单独解析，改完重新生成即可，未改的项沿用上面的默认值。

改这些会让地图重新渲染的项要留意：`render_radius`、`remove_caves_below_y`、`min_inhabited_time`、`hires_enabled`。BlueMap 会按新范围清理范围外的瓦片。



`POST /api/instances/<id>/map/config`，body `{"mc_version": "1.20.1"}`。

它读取实例里**已经存在的**世界目录（`world`、`world_nether`、`world_the_end`），写：

| 文件 | 内容 |
|---|---|
| `config/bluemap/core.conf` | 渲染线程、冷却、webroot、accept-download |
| `config/bluemap/maps/<维度>.conf` | 指向那个世界的绝对路径 |

世界文件不复制、不移动，BlueMap 直接读你原来的。

### 看地图

浏览器打开 `/map/`。面板把它反代到 `map.upstream`（默认 `http://127.0.0.1:8100`）。

### 共享给朋友

`POST /api/map/share` 生成一个带签名的只读链接，形如 `/map/?t=<token>`。有效期由 `map.share_ttl_hours` 控制（默认 24 小时），签名用 `data/secret.key`，不需要给对方账号。

### 玩家位置与 RCON 设置

地图页签下方有一行 RCON 设置：填端口与密码，点「保存并连接」。

- 面板把它写进实例的 `server.properties`（`enable-rcon`、`rcon.port`、`rcon.password`），并保留一份 `.bak`。
- 服务器**运行中不允许改**，接口返回 409，先停服。
- 改完要**重启服务器**才生效；重启后再点一次「保存并连接」，或调用 `POST /api/instances/<id>/map/poll` 开始轮询。
- 轮询按 `map.player_poll_seconds` 拉 `list` 与每个玩家的坐标，数据在 `GET /api/map/players`。

RCON 没开时接口会说明原因，不影响地图本身。

### 标记点

详情页「地图」页签：填名字、X/Y/Z、颜色、备注，点「加标记」。

标记会同时写进两处：

| 位置 | 作用 |
|---|---|
| `data/markers/<实例>.json` | 面板自己存一份，方便增删 |
| `config/bluemap/maps/overworld.conf` 的 `hoshi-panel` 标记集 | BlueMap 真正显示的东西 |

颜色对应 7 个内置图标（红蓝绿黄紫橙白），生成在 `data/bluemap/web/assets/hoshi-<颜色>.svg`。

写入策略：每次增删都会重写标记集，不会叠加重复块。服端正在运行时顺手发一条 `bluemap reload`，没运行就下次启动生效。

标记 API：`GET/POST/DELETE /api/map/markers`，字段 `name`、`x`、`y`、`z`、`color`、`note`；手动重写用 `POST /api/instances/<id>/map/markers/apply`。

### 玩家面板

地图页面右下角由面板注入一块小面板，每 5 秒拉一次 `/api/map/players`，显示在线玩家与坐标。

注入方式是反向代理首页时在 `</body>` 前加一行 `<script src="/map-overlay.js">`。这段脚本不依赖 BlueMap 内部 API，BlueMap 升级也不会失效。

## 6.15.1 长操作的进度与取消

凡是不能立刻完成的操作，页面顶部都会出现进度条，能取消的带「取消」按钮：

| 操作 | 进度来源 | 可取消 |
|---|---|---|
| 导入整合包 | 上传百分比 + 解压条目 | 上传可中断 |
| 导入 zip | 解压条目 | 否 |
| 导出 zip | 已打包文件数 | 是 |
| 创建备份 | 已打包文件数 | 是 |

导出完成后自动开始下载；中途取消会删掉半成品文件。操作结束右下角弹出提示条，成功绿色、失败红色，几秒后自动消失。

进度来自后台任务接口 `GET /api/jobs/{id}`，任务只在内存里，面板重启就没了。

## 6.16 路径浏览

设置页里每个路径项都有「浏览」按钮，打开的是**服务器上的目录树**，不是本机文件对话框。远程管理时按服务器视角选目录。

实例设置里的 Java 路径浏览会列出 `.exe` 文件。

## 6.17 主题与自定义样式

界面默认用 Tabler 的深色主题。设置页「界面主题」可以切 `dark` 或 `light`。

想改细节不用改代码：把覆盖样式写到 `data/theme.css`，页面会自动加载（路径 `/assets/custom.css`，不缓存）。例如改强调色和字号：

```css
:root{
  --hoshi-accent:#ff8800;
  --tblr-body-font-size:.9rem;
}
```

可用的变量：

| 变量 | 作用 |
|---|---|
| `--hoshi-accent` | 强调色 |
| `--hoshi-radius` | 卡片圆角 |
| `--tblr-body-font-size` | 正文字号 |
| `--tblr-font-sans-serif` | 界面字体 |

`GET /api/theme` 会返回当前主题、自定义 CSS 地址与这些变量名，方便脚本化。

## 6.18 字体

整个界面（含按钮、表格、输入框）与控制台都使用 JetBrains Mono，已内嵌约 25 KB 的子集，不装字体也能正常显示。优先使用本机安装的 `JetBrainsMono Nerd Font`，没有就用内嵌版本。

字形只做子集化，没有修改字形。许可证是 SIL OFL 1.1，全文见仓库 `LICENSES/OFL-1.1-JetBrainsMono.txt`。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动失败，提示核心不存在 | 目录或核心文件名不对 | 重新跑 `instances detect` 看识别结果 |
| 启动后立刻退出 | Java 版本不对，或没同意 EULA | 换 Java 17 或 21；把 `eula.txt` 改成 `eula=true` |
| 崩溃栈里有 `ClassMetadataNotFoundException: java.lang.String` | 用 JDK 25 跑 1.20.1 的 Forge，Mixin 直接挂 | 实例设置里把 Java 换成 17 或 21，别用 25 |
| 端口占用 | 25565 被别的程序占用 | 关掉占用者，或改 `server.properties` 里的端口 |
| 日志里中文路径是乱码 | 服端输出编码混用 | 已做自动回退；仍乱就在实例里改 `encoding` 为 `gb18030` |
| 启动要两三分钟 | 大量 mod 的 Forge 服正常现象 | 看控制台是否在持续输出，别急着强杀 |
| 页面打不开 | 端口被占或地址不对 | 看启动日志里的「监听」一行 |

## 8. 安全提醒

**默认只监听 `127.0.0.1`，只有本机能访问。** 这是有意的。

要对外，必须同时满足三件事：

1. 设置 `web.exposure` 为 `lan` 或 `public`。
2. 在 `web.exposure_ack` 里手写确认短语「我确认对外开放」。
3. `public` 档还要求两步验证已开启。

缺一项，面板会拒绝启动并说明原因。启动后在页面顶部常驻一条暴露提示。

登录连续失败达到 `security.login_fail_limit`（默认 5 次）会锁定 `security.login_lock_minutes`（默认 15 分钟），按来源 IP 与账号分别计数。

要远程管理又不想开公网，用 SSH 隧道：

```powershell
ssh -L 25566:127.0.0.1:25566 你的服务器
```

然后本地访问 `http://127.0.0.1:25566`。

## 9. 数据放在哪

| 路径 | 内容 | 删了会怎样 |
|---|---|---|
| `hoshi.toml` | 面板配置 | 下次启动重建默认值 |
| `data/instances.json` | 实例清单 | 需要重新 `instances add` |
| `data/hoshi.db` | 审计与元信息 | 记录丢失，不影响开服 |
| `data/logs/instances/` | 各实例日志 | 历史日志丢失 |
| `data/initial-password.txt` | 初始密码 | 不影响已登录会话 |
| 你的服务端目录 | 世界、mod、配置 | 面板从不动这里，除启动时服端自己写 |
